# Introduction

> Here we briefly summarize why git is part of our educational program.

## Why Git?

Git is software for **version control**: it keeps track of changes to files over time. This makes it possible for multiple people to work on the same project and combine their contributions without constantly passing different versions of files back and forth via email.

Version control also means that you can go back to an earlier version of your project. If something breaks, you can inspect a previous, stable version, compare what changed, or even restore it. In other words, experimenting becomes much less risky: you always have a record of where you came from.

Platforms such as GitHub and GitLab build on Git and provide additional tools for collaboration. You can review and comment on code, report issues, discuss changes, and manage a project together.

Git is useful beyond software development. In a research project, for example, you can use it to keep track of your analysis code and document how your results were produced. This makes your workflow more transparent and reproducible.

## From zero to hero

We expect **no prior knowledge of Git** at the start of this project. Git can feel a little overwhelming at first—it certainly did for us, but you will learn by using it.

As you become more comfortable with Git, you will probably discover useful features that you did not even know existed. Most of those are not covered here: this introduction focuses on the basics you need to get started.

You do not need to understand everything at once. Start with the basic workflow, use it regularly, and build from there.
